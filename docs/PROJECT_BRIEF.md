# 回声 Echo — Project brief

## Problem

很多有价值的信息只有在刚刚发生之后，用户才意识到需要保存。手机要求用户提前开始录像或录音，错过后无法追回；智能眼镜则天然处于第一视角，并能通过一句话即时触发。

## Target user and scenario

- 临时听到电话号码、地址、约定或操作步骤的人
- 维修、巡检、学习等双手被占用的现场用户
- 想保存刚刚看到或听到的生活瞬间，但不希望持续录像的普通用户

## Core interaction

1. 用户主动开启回声。
2. 应用只在内存中滚动保留最近一分钟声音。
3. 用户说“Rokid，回声”。
4. 眼镜拍摄触发时刻画面并冻结前一分钟声音。
5. 服务端保存媒体，生成转写和摘要。
6. 眼镜显示一张简洁的回声记忆卡片。

## AI capability

- 音频转写
- 触发画面理解
- 跨模态情境摘要
- 人名、数字、地点、约定和物品线索保留

## Success criteria

- 连续运行至少 10 分钟，缓冲始终只保留最近 60 秒
- 从语音触发到画面冻结小于 2 秒
- 触发后媒体保存成功率达到 95% 以上
- 中文清晰语音的关键信息可被摘要正确保留
- 未触发片段在停止或退出后不可恢复

## Constraints and risks

- AIUI 录音和相机都受交互权限门控，首次必须由用户主动开启。
- 当前语音事件主要表示唤醒词命中，完整命令文本需要宿主进一步开放。
- 页面切入后台时不保证继续录音，本 demo 会主动停止并清除缓冲。
- 持续录音的功耗、发热和系统音频中断需要真机测量。
- 触发片段可能包含旁人信息，必须有清晰状态提示、主动触发和删除机制。
